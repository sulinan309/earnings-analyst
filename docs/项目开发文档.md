# 个股状态识别工具 — 项目开发文档

> 量化状态机 v2.0 · Phase 1（状态识别器）
> 配套上层框架：泛化买卖点与仓位治理框架 v1.3 / Owner's Earnings 财报分析（本仓库 `main.py`）
> 代码位置：`src/state_machine/`，CLI：`state_tool.py`，测试：`tests/test_state_machine.py`

---

## 1. 项目背景与定位

本仓库原有能力是**财报基本面分析**（李录 Owner's Earnings 框架，v1.3 层），解决"做什么"：
投资哲学、买卖规则、仓位治理、组合约束、决策日志。

本工具是 **v2.0 量化实现层**，解决"怎么自动识别状态"。核心分工：

| 角色 | 职责 |
|------|------|
| 量化（本工具） | **稳定识别状态**，输出置信度与证据，不预测涨跌、不替人做决策 |
| 人工（保留） | 价值锚设定、基本面判断、组合约束、最终决策 |

系统**不输出"买/卖"信号**，而是输出文档第十节规定的 7 项：

```
当前状态 + 状态置信度 + 触发证据 + 数据质量 + 组合约束 + 建议动作 + 是否需写 Decision Log
```

底层哲学：底部/顶部都是事后定义，当下可识别的是"状态变化"而非"极值点"。
买点等卖压衰竭+主动买盘，卖点等上涨衰竭/假设失败/趋势破坏——主动牺牲点位精度，换胜率与低回撤。

## 2. 8 个状态

| # | 状态 | 类型 | 含义 |
|---|------|------|------|
| 1 | 下跌加速 | 风险 | 持续创新低、放量，卖压主导，不抄底 |
| 2 | 下跌衰竭 | 普通 | 下跌动量衰减但未反转，还不是买点 |
| 3 | 弱反弹 | 普通 | 反弹但质量未确认，可能是技术性喘息 |
| 4 | 有效反弹 | 普通 | 收复关键位+买盘主动，可考虑战术仓 |
| 5 | 趋势修复 | 普通 | 连续站稳核心位、板块同步修复 |
| 6 | 上涨衰竭 | 普通 | 上涨动量减弱，进入利润保护观察 |
| 7 | 放量派发 | 风险 | 放量但涨不动，顶部/阶段顶信号 |
| 8 | 趋势破坏 | 风险 | 趋势被破坏，战术仓退出、核心仓复盘 |

**风险状态（下跌加速/放量派发/趋势破坏）**：仍在恶化中、需立即响应，可直接覆盖，不等待防抖。
**普通状态（其余 5 个）**：处于过渡中、需时间确认。

## 4. 核心算法

### 4.1 四层加权评分（第三节）

```
状态总分 = Σ(层得分 × 层权重) / 100
层得分   = 该层 checkbox 满足比例 × 100
```

四层固定：**价位层 price / 成交层 volume / 指数层 index / 资金层 flow**。

分数分级与动作档位：

| 分数 | 等级 | 动作档位 |
|------|------|---------|
| 0–39 | 未触发 | 不交易 |
| 40–59 | 观察 | 只观察 |
| 60–74 | 弱确认 | 允许小仓战术 |
| 75–84 | 有效确认 | 允许标准战术 |
| 85+ | 强确认 | 更高置信度（仍受组合约束） |

### 4.2 权重映射（第七节）

```
最终权重 = 基础状态权重 + 标的画像修正项
约束：单层 ∈ [10%, 45%]，四层合计 = 100%，每次修正后归一化
```

实现为**迭代 clip + normalize**（`resolve_weights`），确保单次归一化令贴边层越界后仍收敛到 10%–45% 边界。

9 类画像修正项（`PROFILE_ADJUSTMENTS`）：港股科技 / A股成长 / 美股大型科技 / 周期商品 /
红利银行 / 小盘高波动 / 高流动性大盘 / 强政策敏感 / 强事件驱动。

**验证（腾讯有效反弹）**：基础 `价35/成20/指30/资15` + 港股科技 + 高流动性大盘
→ `价35 / 成15 / 指35 / 资15`，与文档第七节示例一致。

### 4.3 硬门槛（第四节）—— 回答"状态是否有资格成立"

通用硬门槛：
- 至少 1 个 A 类数据触发（价位/成交/指数层），B 类不能单独触发
- 核心层（基础权重最高层）得分 < 60 → 状态无效
- 趋势破坏等普通买点需收盘确认

各状态另有专属结构门槛（如有效反弹要求价位层 ≥60 且无强红旗且指数非系统性破位）。
**硬门槛优先于总分**：再高的总分也不能绕过结构缺陷。

### 4.4 A/B/C 数据分级（第六节）

| 等级 | 用途 | 层归属 |
|------|------|-------|
| A 类（OHLC/成交/指数/行业指数…） | 可主触发 | 价位/成交/指数层 |
| B 类（南向北向/大单/主动买卖盘/资金净流入…） | 仅加减分，须与 A 类交叉验证 | 资金层 |
| C 类（经纪席位/挂单墙/社媒情绪…） | 仅入 Decision Log | 不进引擎 |

价位/成交层恒可评估；指数层需提供指数数据；资金层需 B 类数据，缺失则整层得分 0 且数据质量降级。

### 4.5 防抖优先级（第五节）

```
风险覆盖 > 硬门槛 > 状态冷却 > 连续确认 > 普通评分
```

- **风险状态**：触发即立即覆盖，不等待、不受冷却。
- **普通状态**：需连续 2 周期确认；未确认时**维持上一状态**（本期仍有效则沿用，否则退回观察），
  候选仅作 `pending_state` 透出。

### 4.6 数据质量与置信度降级

| 数据齐备度 | 质量 |
|-----------|------|
| OHLCV + 指数 + 资金 | 高 |
| OHLCV + 指数 | 中 |
| 仅个股 OHLCV | 低 |

置信度（高/中/低）以总分为基线映射，遇以下情形各降一级：数据质量低 / 政策未落地 / 事件未结束 / 处于 pending 待确认。

## 5. 关键数据结构

```python
Bar(date, open, high, low, close, volume)          # 单根 K 线，A 类
KeyLevels(prior_low, prior_high, first_key_level,   # 关键价位=价值锚（人工可指定，
          core_level, short_support)                #   留空则由近端波段自动估算为代理值）
FlowData(net_flow, prev_net_flow, big_order_net,    # 资金层 B 类，全可选，缺失=该层不可用
         active_buy_ratio, southbound_net, ...)
MarketData(ticker, bars, index_bars, industry_bars, # 一次评估的全部行情输入
           key_levels, flow, intraday_confirmed)

TargetProfile(name, ticker, tags, asset_tier,       # 标的画像；tags 驱动权重修正
              policy_pending, event_pending)
PortfolioConstraint(current_position_pct,           # 组合约束（人工保留项）
                    max_position_pct, holding_tactical)
EngineInput(market_data, profile, portfolio,        # 引擎入参
            previous_state, candidate_confirmations,
            penalties, fundamental_redline)

StateResult(state, score, score_level, confidence_level,  # 引擎输出（7 项 + 透明化明细）
            evidence, layer_scores, weights, data_quality,
            allow_add, only_reduce, action, log_required,
            raw_state, debounce_note, pending_state, all_evaluations, ...)
```

## 6. 使用方式

### 6.1 CLI

```bash
python state_tool.py --demo valid_rebound --show-candidates   # 有效反弹示例
python state_tool.py --demo distribution                      # 放量派发（风险立即覆盖）
python state_tool.py --csv data.csv --ticker 0700.HK --tags 港股科技 高流动性大盘
python state_tool.py --demo valid_rebound --confirmations 1   # 演示防抖未确认时维持观察
```

CSV 列：`date,open,high,low,close,volume`，可选 `index_open,...,index_close,index_volume`（升序，末行为评估日）。

### 6.2 编程接口

```python
from src.state_machine import (
    Bar, MarketData, KeyLevels, FlowData,
    TargetProfile, StateEngine, EngineInput, PortfolioConstraint, format_report,
)

md = MarketData(ticker="0700.HK", bars=[Bar("2026-06-09", 312, 326, 311, 324, 165), ...],
                index_bars=[...], flow=FlowData(net_flow=8.0, prev_net_flow=-3.0),
                key_levels=KeyLevels(prior_low=295, core_level=315))
profile = TargetProfile("腾讯", "0700.HK", tags=["港股科技", "高流动性大盘"], asset_tier="顶级资产")
result = StateEngine().evaluate(EngineInput(
    market_data=md, profile=profile,
    portfolio=PortfolioConstraint(current_position_pct=0.05, max_position_pct=0.15)))
print(format_report(result))
```

### 6.3 输出样例（有效反弹，节选）

```
当前状态：有效反弹      状态分数：96.2      状态等级：强确认      置信度：高
四层得分：价位层 100  成交层 75  指数层 100  资金层 100
当前权重：价位层 35%  成交层 15%  指数层 35%  资金层 15%
硬门槛：通过   防抖状态：普通状态已连续确认 2 周期
组合约束：允许加仓   建议动作：标准战术仓   Decision Log：必须记录
```

## 8. 开发记录（已修复的关键缺陷）

| # | 严重度 | 问题 | 修复 |
|---|--------|------|------|
| 1 | 高 | 有效反弹「放量上涨」与「缩量止跌后次日放量上攻」判据完全相同，两 checkbox 联动虚高成交层 | 新增 `contraction_then_expansion` 特征（前日缩量止跌+当日放量上攻），两路径独立 |
| 2 | 高 | 防抖自相矛盾：注释称"维持上一状态"，代码却采纳新状态，连续确认形同虚设 | 未确认时真正维持 `previous_state`（本期有效则沿用，否则观察），候选仅作 pending |
| 3 | 中 | 下跌衰竭「缩量」与「卖压释放后成交回落」同为 `vol_contraction`（隐藏重复） | 后者改用 `vol_receding`（成交较前一日回落），独立 |
| 4 | 低 | 趋势修复「形成上升结构」AND 当日 `up_day`，误杀健康回踩日 | 改为多日结构 `higher_low AND higher_high`，不绑定当日涨跌 |

## 9. 设计边界与已知约束

- **关键价位是价值锚**：`KeyLevels` 未指定时用近端波段代理（5日均线≈第一关键位、20日均线≈核心位），
  代理值仅供缺省，生产应由人工或 v1.3 显式注入。
- **下跌衰竭成交层结构性封顶 75**：缩量路径与放量路径互斥，4/4 几乎不可达——这是文档 checkbox 结构的设计特性，忠实于原文保留。
- **防抖的连续确认次数**由调用方以 `candidate_confirmations` 传入（单次评估工具无法自持历史周期计数）。
- **误判反馈/复权（第八节）**当前仅在 `EngineInput.penalties` 预留阈值加分接口，完整误判统计窗口与归因记录尚未实现。
- 工具只识别状态，**不替代价值锚、基本面判断、组合约束与最终决策**。

## 10. 后续路线图

- **Phase 2 · 误判反馈闭环（第八节）**：误判窗口（短20/中60/长120 交易日）、误判分级（轻/中/重）、
  归因标签、惩罚复权机制，接入 Decision Log。
- **标的画像数据库**：先做 7 只持仓（美团/快手/小米/腾讯/阿里 + 2），固化 tags 与关键价位。
- **数据接入**：对接固定行情源（口径固定，禁止临时切换平台），自动拉取 OHLCV/指数/B 类资金。
- **与 v1.3/财报层联动**：状态机的组合约束与 `asset_tier` 复用 Owner's Earnings 的赔率分层与仓位治理。
- **回测**：用历史数据验证状态识别胜率，驱动权重与阈值调参。
